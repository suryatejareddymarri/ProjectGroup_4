Purpose
-------
This document explains the current streamlit_app.py file from top to bottom.
The source file is 177 lines long. Blank lines are included only to make the
source easier to read; they do not perform an action. The explanations below
cover every non-blank line or closely related line group.

What the program does
---------------------
The program models a small web search engine. It stores eight fictional pages,
calculates PageRank from the links between those pages, matches a user's search
words, combines relevance with authority, and displays the result in a browser.
Streamlit lets the interface be written in Python.

How to run it
-------------
From the ProjectGroup_4 folder:

  python3 -m venv .venv
  .venv/bin/pip install -r requirements.txt
  .venv/bin/streamlit run streamlit_app.py

Open the local address printed by Streamlit, usually http://localhost:8501.

PART 3: CALCULATING PAGERANK
============================

Line 68: @st.cache_data
This is a decorator. A decorator changes how the function below is handled.
Streamlit remembers results for inputs it has already seen, so it can avoid
repeating the same calculation unnecessarily.

Line 69: def calculate_pagerank(damping: float, iterations: int) -> dict[str, float]:
This defines a function named calculate_pagerank.

The function receives two inputs:
- damping is a decimal such as 0.85.
- iterations is a whole number such as 20.

The return annotation says the function returns a dictionary whose keys are
strings and whose values are decimal numbers.

Line 70: total_pages = len(PAGES)
len counts how many items are in PAGES. Here total_pages becomes 8.

Line 71: scores = {page["id"]: 1 / total_pages for page in PAGES}
This creates the initial score for every page. Every page starts equally, so
each receives 1 divided by 8. The expression is a dictionary comprehension,
a compact way to build a dictionary by looping through PAGES.

Line 73: for _ in range(iterations):
This repeats the ranking calculation. range(iterations) creates the requested
number of rounds. The underscore means the loop number itself is not needed.

Lines 74-76: create next_scores
Every new score starts with (1 - damping) divided by total_pages.
With damping 0.85, this is the small amount of authority distributed evenly
to every page. This prevents a page from receiving zero authority forever.

Line 77: for page in PAGES:
This loops through every page and asks it to distribute its current authority.

Line 78: share = scores[page["id"]] / max(len(page["links"]), 1)
The page's score is divided among its outgoing links. max(..., 1) prevents
division by zero if a page has no links.

Line 79: for target in page["links"]:
This loops over each destination linked from the current page.

Line 80: next_scores[target] += damping * share
The destination receives the source page's share multiplied by the damping
factor. This is the main authority-transfer step in PageRank.

Line 81: scores = next_scores
After one round, the new scores become the scores used by the next round.

Line 83: return scores
After all iterations finish, the function gives the final authority dictionary
back to the caller.

The PageRank idea in one formula
--------------------------------
For a destination page A:

  PR(A) = (1-d)/N + d * sum(PR(B) / L(B))

N is the number of pages. d is the damping factor. B is a page linking to A.
L(B) is the number of links leaving B. Important pages pass more authority to
the pages they link to.

PART 5: SEARCHING AND COMBINING SCORES
=======================================

Line 90: def search_pages(query: str, damping: float, iterations: int) -> list[dict]:
This defines the search function. It accepts the user's query and the two
PageRank controls, then returns a list of result dictionaries.

Line 91: ranks = calculate_pagerank(damping, iterations)
The search always uses current PageRank scores. If the user changes a slider,
this call uses the new values.

Line 92: maximum_rank = max(ranks.values())
This finds the largest authority score. It is used to normalize other scores
so the strongest page has authority 1.0, or 100 percent.

Line 93: terms = tokenize(query)
The user's search phrase is converted into a list of lowercase search terms.

Line 94: results = []
This creates an empty list. Matching pages will be added to it.

Line 96: for page in PAGES:
The function examines each page one at a time.

Line 97: words = tokenize(f'{page["title"]} {page["text"]} {page["domain"]}')
The title, description, and domain are joined into one string and split into
words. These are the words that can match the query.

Line 98: hits = sum(words.count(term) for term in terms)
For every query term, count how often it appears in the page words. sum adds
those counts together. More matching words mean stronger relevance.

Line 99: relevance = min(hits / len(terms), 1) if terms else 0
If the query has words, hits is divided by the number of query terms. min
prevents relevance from going above 1. If the query is empty, relevance is 0.

Line 100: authority = ranks[page["id"]] / maximum_rank
This converts the PageRank score into a relative authority from 0 to 1.

Line 101: if relevance or not terms:
Only pages with a keyword match are shown for a non-empty query. If the query
is empty, all pages are allowed through.

Lines 102-107: results.append({...})
A matching page is copied into a new result dictionary. **page copies the
original page fields. The new fields store relevance, normalized authority,
and the final score.

Line 104: "relevance": relevance
Stores the text-match score for later display.

Line 105: "authority": authority
Stores the normalized PageRank score for later display.

Line 106: "score": relevance * 0.68 + authority * 0.32
This is the final ranking formula. Text relevance contributes 68 percent and
PageRank authority contributes 32 percent.

Line 109: return sorted(results, key=lambda page: page["score"], reverse=True)
sorted orders the matching pages. key says to use each page's score. reverse
True means highest scores appear first. lambda is a small unnamed function.

THE COMPLETE USER FLOW
======================
1. Streamlit starts and runs the Python file from top to bottom.
2. PAGES defines the miniature web graph.
3. The sidebar collects damping and iteration settings.
4. The search box collects a query.
5. calculate_pagerank sends authority through the links.
6. search_pages measures word matches and combines both scores.
7. graph_text creates the graph description.
8. Streamlit displays results, graph nodes, and the authority table.
9. When a widget changes, Streamlit reruns the script with the new values.

Beginner vocabulary
===================
- Variable: a name that stores a value.
- List: an ordered collection of values.
- Dictionary: a collection of key/value pairs.
- Function: reusable code that performs a task.
- Parameter: an input accepted by a function.
- Loop: code that repeats.
- Condition: code that chooses whether something should happen.
- Return: the value a function sends back.
- Module: reusable code imported from another package or file.
- Decorator: syntax that changes or adds behavior to a function.

Important limitation
====================
The graph and pages are manually created in PAGES. The app does not download
real websites, crawl the internet, store user accounts, or use a production
search index. Its purpose is to make the core PageRank idea easy to see.
